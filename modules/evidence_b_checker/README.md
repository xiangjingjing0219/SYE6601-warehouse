# 证据链 B：故障补偿证据检查器

检查合同、故障记录和工单能否支撑补偿判断。每项检查保留原文位置、证据编号和审核结果：支持、反驳、未知或冲突。补到新材料后重新判断，并保留之前的结果。

例如，某份客户合同要求在故障发生后 24 小时内提交工单。查到合同只能确认有这项要求；还没查到工单时，“是否按时提交”仍是未知。取得适用工单后，才比较故障时间和提交时间。

## 如何运行

用 Colab 打开 [岗位验收演示.ipynb](岗位验收演示.ipynb)，按顺序运行。演示使用 CPU，离线回放已保存的模型记录，不需要 API 密钥。

## 联调与验证结果

| 检查内容 | 结果 |
| --- | --- |
| 故障补偿联调案例 | 63 个合成案例和 7 个边界案例，共 70 个，均符合预期 |
| 原检查器回归测试 | 39 项通过 |

边界案例覆盖错客户、错事故、记录过期、缺少版本、同一工单编号内容冲突、提交时间晚于查询时间，以及截止前查到空结果。上述数字是开发验证结果，不代表实际业务准确率。

## 统一模拟工具联调

在仓库根目录运行 `python modules/evidence_b_checker/run_unified_checker.py`。运行时读取同级仓库目录 `loop_b_unified/`；两个目录来自不同下载位置时，在命令末尾加 `--loop-dir "你的loop_b_unified目录路径"`。使用 CPU，无需模型密钥。

检查器接收政策、事故、合同、维护和工单回执，先用原文位置核对引用。只有“计划维护”而没有可核实的免责依据时，维护条件保留“未知”；条款上下文拿不到时，也不能据此认定客户不符合条件。

本轮实际运行 14 个合成场景。前 13 个场景的总体判断与统一工具演示记录一致；第 14 个单独验证“有引用但上下文不可取得”。逐例结论、缺口及工具错误见 [本轮结果](examples/unified_results.json)。这些是接口联调结果，不是独立测试准确率。

## 接收候选证据图

在本文件所在目录运行以下命令，检查候选图及合同引用。使用 Python 3.10 或更高版本，无需安装插件。

```
python proposal_intake.py examples/proposal/input.json examples/proposal/receipts.json ../../loop_b_unified/tool_registry.json
```

输入是候选图、原始查询回执和工具清单。样例提案是为联调构造的；与之对照的合同第二页来自统一工具的实际模拟回执。输出将“能定位到合同原句”和“原句是否支持这个条件”分开。没有独立语义复核时，关系保留未决，不发布补偿结论。已有独立人工复核可通过 `--human-reviews` 传入：以输出中的 review_key 为键，记录 reviewer、decision 和 reason。内容或回执变更后须重新审核。

已读取五条规则的编号、适用范围、优先级和所需来源。目录中的阈值不是具体客户的合同证据，也不替代原有流程。待对齐：①规则中的监控、工单等来源名与实际工具名是否对应；②试用规则的 exemption 节点如何用候选图允许的类型表达；③来源定位目前支持统一回执的完整 citation 字符串，其他编码须提供样例。尚无正式候选实例时，不能把本例当作全流程验收。

## 新旧 Loop B 对接
新版会通过统一包入口取得工具；主分支旧入口仍可使用。运行候选图检查命令时，可在末尾加上以下参数读取新版对接说明：
`--alignment ../../loop_b_unified/dev_checks/interface_alignment_20261113.json`。旧版没有此文件时，省略即可。

规则来源分为已经注册、待确认对应、没有候选工具。待确认名称只用于显示，不会改写查询。结果保留文档编号、来源类型、记录编号、调用编号与原始字符位置；其中 record_locator 指整条记录，不是截取短句的单独位置。缺客户、事故或事件时间会列出缺项，不补演示值。字符串引用仍按先前演示约定解析，尚未作为团队标准签认。
