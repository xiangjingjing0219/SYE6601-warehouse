# 证据链 B：工业日志确定性审核

本轮在日志接收基础上增加有限范围的逐结论审核。唯一运行输入是工业日志 JSON，不读取配套案例说明。只对能定位、能复算的关系给结果；其他文本保留未审核。它不是完整自动建链器，也不是覆盖全部场景的语义模型。

## 本轮运行

60 条全部输出处理状态，5 条得到局部审核图，55 条标记 needs_candidate_graph。没有处理异常。共输出 12 项局部检查：5 项 SUPPORT、3 项 REFUTE、4 项 UNKNOWN。这是检查项分布，不是案例准确率，也不是整条回答的等级。

| 场景 | 已有的局部审核 | 保留的边界 |
| --- | --- | --- |
| IND-002 | 工单已完成、系统显示可启动均有对应字段；完整开机许可保留 UNKNOWN | 不将 ready_to_start 当成所有业务条件已满足 |
| IND-024 | 21500 kPa 换算成 21.5 MPa，反驳回答中的 21500 MPa；读数位于日志给出的正常区间 | 未对整段建议或真实设备安全作背书 |
| IND-030 | 全库“未找到”缺少完整查询依据；工具明确报告材质筛选未生效 | 分页候选参数只作 Loop 对接信息，不执行查询 |
| IND-043 | 已查白班中班为 4200 件；次日夜班不能补目标日 | 标明目标夜班区间和 business_date，原全天数保留 UNKNOWN |
| IND-053 | 18 吨超过日志中 15 吨限制，反驳“可以正常作业”；许可为待审批 | 降低载荷也不能自动让全部条件通过 |

程序不以 case_id 判断结果。只在规定字段和有限句式确实出现时启用检查；改案例编号不改变判断。不能匹配的表述交 A 建链或人工复核，不能据此推断“没有错误”。

## 输出和接口

```sh
python modules/evidence_b_checker/run_industrial_review.py 工业日志.json --output-dir modules/evidence_b_checker/examples/industrial_review
python -m unittest discover -s modules/evidence_b_checker -p 'test_*.py'
```

Python 接口：`industrial_review.review(log, previous=None)`。previous 必须属于同一 case_id/run_id。输出包含：

- 原始日志与内容指纹；图、答案及规则版本。
- 工具调用 → 原始字段 → 代码检查 → 局部结论的有向关系。
- checks：四态、理由、复算值及引用。
- gaps：影响的结论、缺失信息和已知候选参数；全部为 not_executed。
- history/changes：重算前后的快照和变更。当前采用全量重算保证结果一致，尚未做按依赖局部重算优化。
- unreviewed_answer：保留完整回答，明确局部检查不能覆盖全部原子结论和用户目标。

`combine(states, 'AND'/'OR')` 提供四值传播内核。空条件集为 UNKNOWN。实际充分路径及共同必要条件须由经过核对的候选结构提供，当前未自行构造替代路径。

上述是 B 本地审核输出，尚未宣称与 A 的最终新格式一致。现有旧场景 reviewer、提案接收入口和历史测试保留。

## 验证

72 项测试通过（此前 59 项，加上本轮 13 项）。新增测试覆盖五个需求场景、换单位、删除读数、错误设备标识、工具失败携带旧数值、重复来源、改案例编号、引用回读、AND/OR、错误历史绑定，以及补入目标日期夜班后的版本重算。补夜班是明确的受控测试，不是真实补证，也没有改动原始数据。

## 仍需对接

1. A 的完整主张、目标、条件和关系提案：用于覆盖有限句式之外的其他结论和 55 条未分析日志。已有 Schema 可继续讨论复用，不重复索要旧材料。
2. 自由文本关系需要实际语义模型记录或人工审核；本轮没有调用在线模型，不声称混合方案已验收。
3. Loop 接收 B 缺口并确定实际计划；现有输出仅提供已知字段与缺口。工具名出现在日志中不意味着有可调用服务。
4. 评分组决定分项评分；本轮不新增分数、权重或准确率。独立验收标注须根据原始 JSON 制作，不能使用配套案例说明标签。

本轮可交付 B 的可复算局部审核模块；完整系统仍须上述接口联调。
